**D-181 — Onboarding wizard: progress on the user, persona order, the app's own forms per step** · Accepted (MVP-108, 2026-11-15) · Builds on D-083, D-125

MVP-108 left open where progress lives, what "skippable" records, the persona variants and who sees the wizard. →
**State:** `users.onboarding_state JSONB NULL` (`{status: ACTIVE|DISMISSED|COMPLETED, step, done[]}`, Zod-validated,
steps `ACCOUNT, OFFICE, INVITE, TOUR, CASE, HEARING, DOCUMENT, DONE`); **null = never offered** (an invited colleague).
**Signup** (D-083) writes `{ACTIVE, OFFICE, [ACCOUNT]}` for the new manager. `GET /users/me/onboarding` → `{state}`;
`PUT /users/me/onboarding` saves it as sent (own row only, no permission — like the profile; allowed while read-only;
**not audited**: UI progress, not office data). **Steps per persona** (the office's `accountType`): SOLO skips INVITE (7
steps), FIRM invites before the office setup, CORPORATE the default order — "Step n of N". **Next** marks the step done,
**Skip** moves on without it, **Back** goes back; **Finish** on the last step → COMPLETED; "Don't show again" →
DISMISSED; both return to the dashboard. **Who:** `/onboarding` sits behind `manage:office` (its steps set up the office);
the profile menu's "Setup guide" reopens it (ACTIVE again from the first step, the done steps kept); the dashboard shows
a "Continue setup" nudge while ACTIVE. **Steps reuse the app's forms:** office setup = `PATCH /offices/me` (jurisdiction,
language, currency, time zone), invite = the team's invite modal, tour = four short localized cards, first case = the
quick-create modal, first hearing = pick a case (newest first) + the hearing form (office reminder defaults), first
document = pick a case + the upload panel, done = the checklist (done / skipped) with links. After signup the app opens
`/onboarding`. **Not done:** the Cypress "< 5 minutes" journey (component tests cover resume, persona order, skip, dismiss,
finish and Arabic/axe), help-centre links (the Help Center story), a guided overlay tour.
