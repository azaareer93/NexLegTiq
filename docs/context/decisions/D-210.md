**D-210 — Empty states and the dashboard's quick-start checklist: ticks from office data, dismissal per browser** · Accepted (MVP-109, 2026-11-21) · Builds on D-151, D-181, D-185

MVP-109 left open where the checklist's ticks come from, who sees it, where "dismissed" is kept and what the illustrated
empty states are. → **Ticks:** `GET /dashboard` gains `setup` — six booleans `client, case, hearing, document, colleague,
aiSummary`, each an office-wide existence check on the scoped client (a live client; a live case; a hearing not cancelled on
a live case; a live document; another active user or any office invitation; any AI summary), re-derived on each load (seven
`LIMIT 1` queries, managers only), yes/no only, confidential files included like the
team counts (D-151) since nothing of them is shown. No schema change and no stored progress: the ticks are derived, so they
can never drift from the data. **Who:** `setup` is null without `manage:office` — the same people the setup wizard is for
(D-181); invited colleagues join an office that is already set up. Those without it keep the "first case" prompt in an
empty office. **Checklist:** on the dashboard under the wizard's nudge, "n of 6 steps done" with a bar; each open step links
to where it is taken (Clients, the quick-create case dialog, Cases for hearings and documents — both live on a case —, Team,
the AI summaries guide); it disappears when all six are ticked. **Dismissal:** the close button stores
`nexlegtiq.quickStart.dismissed.<userId>` in `localStorage` (a UI preference; a refused write hides it for the visit). Per
browser, not per user — cheap to move onto `users.onboarding_state` later if offices ask for it to follow them.
**Empty states:** `EmptyState` (shared-ui) takes `illustration` (`start | cases | clients | calendar | documents`): original
inline SVG line drawings in the theme's tokens, symmetric so they need no mirroring in RTL, `aria-hidden`. The first-run
empty states of Cases, Clients, the Calendar and a case's Documents tab show the drawing, their main action (new case, new
client, "Schedule a hearing" → the cases list, upload — each behind its permission) and a "How it works" link to the
matching Help Center guide (D-185) — Clients, which has no guide of its own, links "Getting started"; filtered-empty states
keep their "clear filters" action and no drawing. The calendar has no filtered state: any empty period shows it. **Scope:**
these are the four pages whose first item the ticket names (case, client, hearing, upload); Tasks, Invoices and Team keep
their plain empty states — their first item comes from a case or an invitation, which the checklist already leads to.
