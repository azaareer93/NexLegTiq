**D-180 — Audit UI: the log read by cursor, a file's rows through their values, a capped synchronous CSV** · Accepted (MVP-105, 2026-11-15) · Builds on D-019, D-076, D-158

MVP-105 left open how a file's audit is found (audit rows carry no file id), how big an export may be and what "async for
large ranges" means for the MVP. → **API** (`modules/audit-log`, all `view:audit` — OM and Admin): `GET /audit?entityType&
entityId&userId&action&from&to&cursor&limit` (newest first, `{items, nextCursor}` as the timeline, `limit` 1–100, default
50; `from`/`to` are **office calendar days**, both included, at most 366 days apart → else 400 `validation.auditRange`);
`GET /cases/:id/audit` (same query; also the file's read access, 404 otherwise) = the rows of the file's own id **and of its tasks, documents, hearings, notes, time entries and witnesses** (by id: views,
downloads and edits that do not repeat the file id), plus rows whose values name it (`fileId`) — child ids read per
request and JSON matched without an index (`shortcut:`; a `file_id` column when a file's audit grows slow). **Every read
and the export leave out the rows of confidential files the caller is not on** (D-096: an Admin holds `view:audit` but
not confidential files), by those same ids — a row naming such a file only in its values (a client or team link) is not
caught (ids, not content);
`GET /audit/export?format=csv&<filters>` → **a CSV file, synchronous, at most 10,000 rows** (more → **422 BIZ-025, new:
"narrow the filters"**), with a UTF-8 BOM, every cell quoted and formula characters defused, times as office wall clock,
field changes as JSON; **each export writes an `EXPORT` audit row** (filters and row count, never the rows). Throttled
10/min. Each entry: time, actor (`USER` with name, `PLATFORM_ADMIN`/`CLIENT`/`SYSTEM` shown as words, never an account
name), action, entity type and id, and `changes [{field, old, new}]` from the stored values (D-019 keeps secrets out of
them). The client gains `requestText` (body kept as text, errors still `ApiError`). **UI:** the file's **Audit tab**
(already gated by `view:audit`, D-096) and **`/settings/audit`** — a menu item "Audit log" with its own `view:audit`
guard (an Admin reads it without `manage:office`; Settings links to it too): table (time, by, action as a word and tag, item type in words, the
fields written), "show older entries", filters in the URL (action, user, item type, from/to that cannot cross) and
"Export CSV" (the app restores the BOM the browser drops). Times on screen follow the user's zone like every date in the
app (D-092); the filters' days and the CSV are office days. **Not done (amends the ticket):** PDF export and the emailed link for very large ranges (narrowing the
dates covers the MVP; an async export job when offices outgrow 10,000 rows per range), field names translated (shown as
stored, LTR), the platform audit (admin panel).
