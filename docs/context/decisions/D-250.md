**D-250 — Autopilot moves a stacked ticket to Done once its code is in `develop`** · Accepted (MVP-174, 2026-11-26) · Builds on D-147
A PR merged into its parent branch (a stack) does not close its Jira issue, and the parent's squash merge into `develop`
closes only the parent's key, so stacked tickets stayed *In Review* with all their code shipped (MVP-80, MVP-81, MVP-100).
→ The owner chose that autopilot closes them: after any merge into `develop`, every MVP issue *In Review* whose PR is merged
and whose changes are in `develop` goes to *Done*, with a comment naming the `develop` commit. "In `develop`" is checked by
content, not ancestry: a squash merge leaves the child's commits off `develop`'s history. Autopilot still never closes an
issue whose PR is open or closed unmerged, and never deletes or re-prioritises issues.
