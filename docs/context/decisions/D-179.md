**D-179 — Session summaries: the minutes in one call, suggested next steps become tasks only when picked** · Accepted (MVP-87, 2026-11-14) · Builds on D-148, D-156

MVP-87 left open where a session summary's extra fields live, when a summary is current, how next steps turn into tasks
and what "auto-offer" means. → **API:** `POST /ai/summaries {sourceType: SESSION, sourceId, language, force?}` (`use:ai`, the
office's AI switch first): the session is seen through its file (D-126 scope, 404 otherwise); no minutes → 422 BIZ-020; a
**current** summary (written after the session's last change, under the current prompt, in that language) → 200, else the
job is queued (202, D-130 quota). `GET /ai/summaries?sourceType=SESSION&sourceId` → the newest current summary per language
(an edit of the minutes — or any edit of the session — makes older rows stale; they stay as history). **Worker**
(`SessionSummarizer`, `ai/summarize-session`): minutes are at most 20,000 characters, so **one call** (`session-summary.v1`,
Zod-validated): `summary`, `keyFacts` ≤ 10, `nextSteps` ≤ 10 `{action, dueInDays: 0–365 | null}`, `riskAssessment
LOW|MEDIUM|HIGH`; redaction context = the file's people (D-131); `SUMMARY_GENERATED` timeline event (ids only) and the new
realtime event `session.summary.ready` to the job's creator. **Schema:** `AiSummary` gains `next_steps JSONB DEFAULT '[]'`
and `risk_assessment AiRiskLevel NULL` (enum `AiRiskLevel`); a session row has `versionNumber` null, so the unique key never
collides and `regeneration` only orders rows. **Tasks:** `POST /ai/summaries/:id/create-tasks {selected: [{index, title?,
dueDate?, assigneeId?}]}` (1–20 distinct indexes, `create:task`; someone else as assignee needs `assign:task`, as a normal
create) makes the picked steps tasks **in one transaction, all or none**, on the session's file, `sourceType AI_NEXT_STEP`,
`sourceId` = the summary, due = the date given, else today in the office's zone + `dueInDays`, else none; an index the
summary does not have → 400 VAL-001 `validation.nextStep`. Nothing is created from the model alone. **UI:** the hearing
drawer shows an "AI summary" card to `use:ai` holders when the hearing has minutes; minutes over **100 words** show an offer
(never an automatic run); the summary shows the risk (tag + word), key facts and the next steps as a checklist with
"Create selected tasks" (for `create:task`), steps already turned into tasks in this view are marked; the AI disclaimer
always shows. **Not done:** remembering across reloads which steps became tasks (the tasks carry the summary as source; a
second click creates a second task), feedback on session summaries (documents only, D-148), editing a step's title, date
or assignee in the drawer (the API takes them).
