**D-189 — Ruflo MCP comes from the ruflo-core plugin, not `.mcp.json`** · Accepted (tooling, 2026-11-20) · Amends D-077

`.mcp.json` declared `claude-flow` as `npx -y ruflo@latest mcp start`, and the ruflo-core plugin (enabled per machine)
registers the same server again as `plugin:ruflo-core:ruflo` (a local `node` launcher). On Windows the npx entry never
started: resolving `@latest` ran for more than 5 minutes, and Claude Code gives up an MCP start after 30s. A per-machine local
override silenced that but caused a "Conflicting scopes" warning. → **One server:** `claude-flow` is gone from `.mcp.json` and
`enabledMcpjsonServers`; the memory read permissions in `.claude/settings.json` name `mcp__plugin_ruflo-core_ruflo__*`;
`/ticket`'s `memory_import` uses the plugin server. Install the plugin per machine (`docs/ruflo.md`). The `npx ruflo@latest`
CLI commands in the docs stay: they run outside MCP's start timeout.
