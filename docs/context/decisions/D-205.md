**D-205 — `ClientInfo` lives in `common/context`; the old auth path is a temporary re-export** · Accepted (backend, 2026-11-21) · Refs D-076, D-081

`ClientInfo`, `clientFromRequest`, `truncateUserAgent` (D-081) and `tenantContextFor` sat in `modules/auth/client-info.ts`,
so most domain modules (about twenty) imported `modules/auth` for a request-context type. → **One file, `src/common/context/client-info.ts`**,
next to `RequestContext`; `tenantContextFor` stays in the same file (it only builds a `TenantRunContext` from a
`ClientInfo`, so splitting it into `common/tenancy` would add a file for one function). Every caller on develop imports the
new path. `modules/auth/client-info.ts` is a one-line `export *` kept only because open branches still add imports of the
old path; delete it once none do. No ESLint `no-restricted-imports` rule for `modules/auth/**` yet: it would fail those
branches' lint after they merge, and other cross-module auth imports (guards, decorators) need an allow-list first.
