**D-183 — Platform usage and health: counts across offices, queue counts by API, the platform audit table** · Accepted (MVP-103, 2026-11-15) · Builds on D-084, D-145, D-180

MVP-103 left open what "usage" counts, how Bull Board reaches the admin panel and which log the platform audit shows. →
**API** (platform realm, `AdminRealmGuard` + `AdminAuthGuard`, read on the raw client: counts and sums, never office
content): `GET /admin/usage?days=7..90` (30 by default) → AI cost per UTC day (`ai_usages.cost_usd`, every recorded
call: cached, partial and failed ones included, since cost is what the provider bills), AI cost and operations by office
and model (top 20), storage by office (sum of document-version sizes, top 20), active users today / this week (by
`lastLoginAt`: sign-ins, not activity — `shortcut:`), and the signup funnel of the period (new offices → manager email
verified → at least one case). Money stays a decimal string. `GET /admin/queues` → waiting/active/delayed/failed per
BullMQ queue (a queue Redis cannot answer for shows zeros). **Bull Board** stays an API-mounted page enabled outside
production only (D-084): the admin panel shows the counts and says where Bull Board lives; guarding it for production
waits for the platform login to cover Express middleware. **Platform audit** = `platform_audit_logs` (what staff did,
refused sign-ins included): `GET /admin/audit?officeId&adminId&action&from&to&cursor&limit` (UTC days, ≤ 366) and
`GET /admin/audit/export` (CSV, ≤ 10,000 rows else 422 BIZ-025, the CSV rules of D-180). **Admin panel:** Usage (stat
tiles, a single-series bar chart of daily cost with a tooltip per bar and a table view, tables by office), Queues
(failed counts as an error tag with icon and words, refreshed every 30 s), Platform audit (filters, older entries,
export); AR/EN. **Not done:** per-office storage against plan quotas, activity-based DAU (needs an activity signal),
Bull Board in production.
