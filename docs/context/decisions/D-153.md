**D-153 — File lifecycle: close, reopen, archive and reassign** · Accepted (MVP-64, 2026-11-09) · Amends D-118, D-140
MVP-64 left the error codes of forbidden transitions, who archives, what reassigning does to the team and whether
archiving needs its own job open. → **Routes** (`src/modules/file-participants`, next to the team because reminders and the
reassignment steps live there): `POST /cases/:id/close` `{reason?, force?, forceReason?}`, `POST …/reopen`, `POST
…/archive` (204 each) and `POST …/reassign` `{newResponsibleLawyerId, note?}` (200, the team). Every transition locks the
file and re-reads its status in the transaction (`lockFile`: deleted → 404, archived → **BIZ-007** for every transition,
reopen included — an archived file is read-only for good, D-052). **Close** (`close:case`; a LAWYER only as the file's
responsible lawyer, D-081 — checked by the service): an OPEN or SUSPENDED file; already CLOSED → **422 BIZ-002**; open tasks
(not DONE) → **422 BIZ-003** with detail `{field: 'force', message: 'validation.openTasks', params: {openTasks}}` unless
`force` with a non-empty `forceReason` (400 VAL-001 otherwise); sets CLOSED and the closing date (today in the office's zone),
cancels the PENDING reminders of its hearings (`ReminderScheduler.cancelForFile`, D-117), `FILE_CLOSED` on the timeline
(`{reason?, forceReason?, openTasks?}`) and an audit row with the reasons. **Reopen** (`reopen:case`, same condition): only a
CLOSED file (else 409 RES-003) → OPEN, closing date cleared, the reminders of its upcoming hearings scheduled again
(`resetForFile`), `FILE_REOPENED`. **Archive** (OFFICE_MANAGER and SENIOR_LAWYER by role — the matrix has no archive
permission; the route needs `close:case`): only a CLOSED file (else 409 RES-003) → ARCHIVED, audited (no timeline type
exists for it). **Reassign** (`edit:any:case`): the team route's reassignment (D-140) — the new lawyer is added as, or
promoted to, RESPONSIBLE_LAWYER and the previous one stays as MEMBER; tasks keep their assignees; `FILE_REASSIGNED` now
carries `reason: 'REASSIGN'` and the note (`'TEAM'` from the team card); **both lawyers are notified** (amends D-140, which
told only the new one: the previous gets `shell.notifications.fileReassignedAway`). **Office app (amends D-118):** the ⋮ menu
offers Close (open or suspended files), Reopen (closed files), Archive (closed files, OM/SL) and Reassign instead of the
"coming soon" dialogs: closing asks a reason and, when the API answers BIZ-003, shows the open-task count and asks why it is
closed anyway; reopen and archive confirm first (archive in red, "cannot be reopened"); reassign picks from the people
directory's OM/SL/L. Each refreshes the file, the lists, the hearings and the dashboard. **Not done:** the optional
"auto-archive N days after close" office setting and its daily job (the ticket marks it optional), an unarchive.
Review additions (same PR): **`FILE_CLOSED` carries no staff text** — it is portal-visible (D-150), so the reason and the
forced-close reason live only in the audit row; the timeline payload holds `{openTasks}` for a forced close. **Archiving also
cancels pending reminders** (a closed file can still get hearings; only archived files refuse them, D-116). `lockFile` now
returns the status it read under the lock (one query less); close and reopen audit the closing date. The reassign note is
on `FILE_REASSIGNED`, which the portal never shows. Arabic wording: إعادة تكليف الملف / أرشفة الملف / إعادة فتح الملف; the
open-task count follows the user's digits with Arabic plural forms. **Known limit:** reassign decides add-vs-promote before its
transaction, so a team change at that instant fails with 409/404 instead of retrying.
