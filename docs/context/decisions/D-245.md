**D-245 — Office app first load: the shell is a lazy route and the route table imports feature `routes` files, not their barrels; initial budget 430 kB; the 2.5 s mobile LCP needs a second step** · Accepted (MVP-173, 2026-11-21) · Builds on D-235
The ticket asks the sign-in and signup pages to load without the shell's chunks, Lighthouse mobile LCP under 2.5 s on
`/login` and the dashboard, and a lower `initial` budget. D-235 measured 674.5 kB gzip preloaded by `index.html` and LCP
7.2 s (mobile, simulated slow 4G, 4× CPU). → **Two causes, two changes in `app/routes.tsx`:** (1) `AppShell` was a static
`element`, so the menu, search, quick-create host, task drawer, timer and notifications bell were in the entry; it is now
the route's `lazy` component (its own chunk, loaded after `RequireAuth` lets a signed-in user through) and no longer
exported from the shell barrel, so nothing pulls it back in. (2) The route table imported `casesRoutes` & co. from each
feature's `index.ts`; a barrel also re-exports components (`QuickCreateCaseHost`, `ClientSelect`, `TaskDrawerHost`,
`InvoiceWizard`, the audit table…) and the bundler keeps a re-exported module in the importer's chunk, so every route's
`lazy` was undone. It now imports `../features/<name>/routes` directly — **rule: the route table imports only `routes`
files; a feature's barrel is for other features**. **Result:** initial 674.5 → **405.8 kB** gzip (the rest is React,
react-router, AntD core with the providers, both locales of `shared-i18n`, zod + contracts + axios for the session);
Lighthouse 12.8 mobile on `/login` **LCP 7.1 → 5.4 s**, FCP 6.7 → 4.7 s, score 0.48 → 0.58, 845 → 624 KiB, unused JS
321 → 158 KiB. CI budget `initial` 700 → **430 kB**. **Not met: LCP < 2.5 s.** At slow-4G speed every 100 kB costs ~0.65 s
here, so the target needs ~450 kB less than React + AntD + i18n weigh — splitting cannot get there. The next levers, each
its own story: (a) load only the active locale of `shared-i18n` (both are bundled today by design, `create-i18n.ts`) and
the auth contracts apart from the whole `shared-api-client`; (b) render the public pages without waiting for the session
restore — `GuestOnly` shows a skeleton until `/auth/refresh` answers, one cross-origin round trip the local run hides
(its API host does not resolve), an auth-flow change for the owner's review; (c) a build-time prerender of `/login` and
`/signup` (static HTML + CSS before the JS). The dashboard was not measured: it needs the API over https (staging).
