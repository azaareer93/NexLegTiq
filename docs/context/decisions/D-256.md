**D-256 — Legal research: Perplexity Agent API, model + `web_search` tool, behind an env flag, answers kept in Redis** · Accepted (MVP-156, 2026-11-27) · Builds on D-057, D-130, D-131, D-144, D-148
The owner accepted Perplexity as a sub-processor for general legal questions only (zero-retention terms, US processing,
redacted question only, DPA with SCCs) and asked for official legal sources first with an open-web fallback.
→ **Flag:** `AI_RESEARCH_PROVIDER` (`none` default · `perplexity` · `fake` for tests/local, refused in production) is the
platform switch; `PERPLEXITY_API_KEY` + `PERPLEXITY_MODEL` are required only with `perplexity`. Off → `POST /ai/research`
answers 503 AI-001 before anything is queued. It is switched on only after the written zero-retention confirmation and the
DPA/FAQ update. Research never uses the summary chain (OpenAI/Gemini) and has no fallback provider.
→ **Model + tools, not a preset:** the request names `PERPLEXITY_MODEL` explicitly with one `web_search` tool, because we
need `filters.search_domain_filter`, a fixed model for `AI_MODEL_PRICES`/evals, and `store: false`. The answer uses
`response_format: json_schema`. The cost is Perplexity's own `usage.cost.total_cost` (tokens + search), not the token table.
→ **Sources first:** the first call is filtered to the official domains of the office's jurisdiction (Al-Muqtafi, gazettes,
courts; `legal-sources.ts`). When it returns no sources, one second call searches the open web. Citations come from the
provider's `url_citation` annotations (else its search results) — never from the model's JSON, so they cannot be invented.
An answer without sources is shown as "unsourced".
→ **No case data:** the request is `{question, language, jurisdiction?}` only. The question is redacted (phones, emails, ids,
IBANs) and the office's own client and party names are hidden as whole names (passed as `organisations`, so a common word
inside a name is not replaced). The audit row (`LegalResearch`, CREATE) stores the redacted question.
→ **Limits accepted:** a name the office does not know (a third party typed by the user) is not hidden — the page asks
not to type case details. The office's names are looked up by the question's words over all rows (people also by their
identifying words), so a question sharing a word with a client's name may lose that word. A same-question 200 is served
from the office's cache without an AI usage or audit row (no provider call). The open-web retry is paid but not counted
against the quota, so at most two paid calls per question.
→ **No new table:** the answer of a job lives in the AI cache (`o:{officeId}:ai:research:job:{jobId}`, 24 h, for its
creator) and under the question hash for the cache TTL (same question → 200). The typed question rides in the `ai` job data (Redis, kept
with completed jobs) so the worker can re-hydrate the answer; it never reaches PostgreSQL. Research is general knowledge, not a record
of the case; a persisted history waits for the multi-turn story.
