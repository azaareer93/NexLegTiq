**D-170 — One file per decision** · Accepted (owner asked for it; MVP-169, 2026-11-13) · Amends D-114, D-147
Every open PR that adds a decision showed as conflicting on GitHub as soon as another merged: `merge=union` (D-114) is honoured
by git but **ignored by GitHub's mergeability check**, so each merge forced a `develop` merge into every other PR. → The log is
now `docs/context/decisions/D-NNN.md`, one entry per file with its text unchanged (128 files split from `decisions.md`, which is
gone; its section headings were dropped — the topic files group subjects already), plus `README.md` (format and how to add).
A ticket adds a new file, so two PRs never touch the same file; picking a number already taken by another open PR is a real
add/add conflict, fixed by renumbering. **Context:** CLAUDE.md can no longer import the whole log (no folder imports), so it
is **not loaded into every session** any more (it was ~3,000 lines); every task greps the decisions of its area first
(CLAUDE.md, `/ticket` step 2, the agents). **Tooling:** the Ruflo seed reads one `decisions` entry per file (key = file name);
the post-merge hook also watches `docs/context/decisions/*.md`; the Notion sync marker is the folder's tree hash
(`git rev-parse HEAD:docs/context/decisions`). `.gitattributes` loses its `merge=union` line. Why: no more false conflicts,
and sessions start without a 3,000-line log in context.
